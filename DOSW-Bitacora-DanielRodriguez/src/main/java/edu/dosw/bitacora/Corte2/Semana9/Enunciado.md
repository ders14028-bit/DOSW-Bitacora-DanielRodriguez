# Escenario 1: Plataforma de Batallas Bakugan

- Una startup quiere lanzar una aplicación web para fanáticos de Bakugan, donde los usuarios puedan coleccionar criaturas, mejorarlas y enfrentarse en combates estratégicos.
- El sistema debe incluir mecánicas de progresión, gestión de inventario y enfrentamientos entre jugadores. A diferencia de otros juegos, los combates no requieren ser en tiempo real, pero sí deben mantener consistencia en los resultados.

- El cliente ha expresado inquietudes relacionadas con:
   - El balance entre criaturas y habilidades
   - La posibilidad de hacer emparejamientos justos entre jugadores
   - La persistencia de la información de las partidas
   - La facilidad de evolución del sistema a futuro

- Se menciona que más adelante podrían integrarse funcionalidades como eventos especiales, rankings y modos cooperativos, pero aún no hay claridad sobre estos.
- Es importante tener en cuenta que el cliente no ha entregado documentación formal, únicamente estas necesidades generales.

## Instrucciones (obligatorio desarrollar):

1. Identificación de requerimientos

   A partir del enunciado, deben extraer TODOS los requerimientos implícitos y explícitos.

   - No se limiten a lo evidente
   - Consideren supuestos razonables (ej: autenticación, persistencia, etc.)
   
2. Clasificación

   Clasifiquen cada requerimiento como:

   - Funcional
   - No funcional
   - Justifiquen brevemente cada clasificación.

3. Redacción correcta

   Reformulen cada requerimiento en formato adecuado:

   - “El sistema debe…”
   - Eviten ambigüedades
   - Sean medibles cuando aplique

4. Priorización

   Asignen prioridad a cada requerimiento:

   - Alta / Media / Baja
   - Justifiquen el criterio (valor de negocio, dependencia, criticidad).
   
5. Identificación de dependencias y bloqueos

   - ¿Qué requerimientos dependen de otros?
   - ¿Qué podría impedir su desarrollo o implementación?
   
6. Matriz de trazabilidad

   Construyan una matriz que relacione como mínimo:

   - ID del requerimiento
   - Tipo (Funcional / No funcional)
   - Caso de uso o módulo asociado
   - Posible prueba o validación
   
7. Análisis de ambigüedades

   Identifiquen al menos 3 aspectos del enunciado que:

   - Sean ambiguos
   - Estén incompletos
   - Requieran validación con el cliente
